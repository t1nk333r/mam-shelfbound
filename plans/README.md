## Targeted UI plan (2026-08-08) — plan 039

Plan 039 responds to the maintainer's assessment that the search and filter
controls look disconnected and visually heavy. Live markup and the committed
desktop/mobile screenshots confirm the cause: both `#searchForm` and
`#filterRow` use `.row`, and `.row` independently supplies a border, rounded
corners, elevated background, and large shadow. When filters appear, the UI
becomes two full card surfaces stacked edge-to-edge; on mobile, the duplicated
chrome is especially prominent and the minimum-seeders input remains an
awkward partial-width control.

The plan wraps both semantic rows in one `search-filter-panel`, moves card
chrome to that parent, and leaves the search form and client-only filter row as
siblings separated by a subtle divider. Keeping filters outside the form is
load-bearing: typing in filter controls must not submit another MAM search.
Desktop controls retain their compact flex layout; mobile controls become
consistent full-width rows. IDs, JavaScript behavior, themes/tokens, backend
requests, and data flow remain unchanged. Plan 039 builds on the already-DONE
filter feature from Plan 016 and is independent of Plans 037 and 038.

## Targeted bug plan (2026-08-08) — plan 037

Plan 037 was requested from the untracked maintainer report
`documrnted-bugs.md`. The report documents audiobook imports failing when
`/downloads` and `/library` cannot hardlink across filesystems, ZFS datasets, or
pools. Live code confirms the report: `hardlink_one` turns `EXDEV` into an HTTP
400 (`app/main.py:1008-1026`), and every audiobook selects that helper
unconditionally (`app/main.py:1251`). Both automatic imports and History Retry
use the shared `import_torrent_to_library` chokepoint, so one policy fixes both
torrent clients and both entry paths.

The plan adds `AUDIOBOOK_IMPORT_MODE=hardlink|auto|copy`. `hardlink` remains the
default to preserve zero-duplication behavior; `auto` falls back only for named
cross-device/unsupported-link errnos; `copy` bypasses links. This is classified
as Tier-1 deployment configuration under ADR-0002 because filesystem capability
and duplicate-storage cost belong to the operator. Plan 037 is independent of
the remaining TODO plans 031, 033, and 034.

## Post-implementation audit (2026-07-24, branch `advisor/plans-001-012` @ `57c0af6`)

Plans 001-012 are all DONE but live on branch `advisor/plans-001-012`, **not
merged**. `master` is still `f8d3d32` with zero source drift, so re-auditing it
would only re-surface the twelve findings already fixed on that branch.

This pass therefore audited the **485 lines the implementation added** — the
torrent-client abstraction, `app/conftest.py`, the new test suite, the rewired
call sites, the CI job, `.dockerignore`. That surface had been reviewed only
*against its own plans*, never audited with fresh eyes for defects the changes
introduced. **Plans 013 and 014 target that branch, not `master`** — both stamp
`57c0af6` and their drift checks reference it.

- **013 — `pytest` can mutate a real database at collection time.**
  `app/conftest.py` uses `os.environ.setdefault("HISTORY_DB_URL", ...)`, so a
  developer with that variable already exported gets *their* database. Because
  `import main` runs `ensure_history_schema()` at module scope, and plan 012 made
  that function mutate rows, merely **collecting** the suite rewrites data.
  Demonstrated: a seeded `importing` row became `added` under
  `pytest --collect-only`, with no test body executing. This is an **emergent**
  defect — plan 001 introduced the env knob and the `setdefault`, plan 012 made
  the schema function mutating; neither is wrong alone, and per-plan review could
  not have caught it. Fix: force the assignment instead of defaulting it.

- **014 — qBittorrent add can record a NULL hash, stranding the row forever.**
  `torrents/add` returns no infohash and registers asynchronously; the follow-up
  `torrents/info` query fires with no retry, so losing the race yields `None` →
  NULL `torrent_hash` → excluded by `torrent_hash IS NOT NULL` in the candidate
  query → never imported, no Retry button. Same stranded-row class plan 012
